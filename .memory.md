## Last session: 2026-09-26 (T2: PE resources + signing)

`build.output.resources` embeds three resources into the artifact, all generated
in Rust (no `rc.exe`/`windres`): `icon` (`.ico` → `RT_GROUP_ICON` + `RT_ICON`),
`version_info` strings → `RT_VERSION`, and `manifest` (UAC level / ui_access /
DPI) → `RT_MANIFEST`. `src/engine/resources/{tree,icon,version,manifest,inject}.rs`;
`inject.rs` appends a `.rsrc` section to the compiled stub (room in the header
slack, `SizeOfImage` + `RESOURCE` directory patched). `resources::embed(pe, cfg)`
resolves the section RVA first because directory offsets are section-relative
while `IMAGE_RESOURCE_DATA_ENTRY.OffsetToData` is an **image RVA** (confirmed
against `notepad.exe`). `--dry-run` builds the blob (rva 0) to validate.
**Validated against Windows APIs**: `FindResource`/`LoadResource` for all types,
`version.dll` (`GetFileVersionInfo`/`VerQueryValue`) for the strings and fixed
file info, `ExtractIconExW` for the icon. Example
`examples/configs/test-resources.yaml` + `examples/assets/sample.ico`.

`build.output.subsystem` (`console`|`windows`) prepends
`#![windows_subsystem = "windows"]` to the rendered stub (skipped if the stub
sets its own) so the artifact links as a GUI app. `build.output.sign` signs the
artifact with `signtool.exe` after resources and before the manifest
(`src/engine/signing.rs`): `lab` creates an automatic **CA + leaf** chain
(self-signed `<subject> Root CA` + code-signing leaf in `Cert:\CurrentUser\My`
via PowerShell) and **exports the CA's public cert** next to the artifact as
`<stem>.ca.cer` for the lab to trust; the build machine's trust stores are
**not** modified. `store` uses an existing cert; `file` signs with a `.pfx`
(`password_env`). `signtool` discovery: PATH → `BATESIAN_SIGNTOOL` → Windows Kits
(`%ProgramFiles(x86)%\Windows Kits\10\bin\<ver>\x64`) → `output.sign.signtool`.
Optional `timestamp_url`. `src/engine/identity.rs` fills
`output.resources.version_info` when `randomize: true` (company/product/
description/versions/copyright; explicit fields win) and its generated company
becomes the lab subject when none is set. The manifest records
`signature.{mode,subject,issuer,thumbprint}` and the resolved `version_info`.
`.pfx`/`.p12`/`.pem`/`.key` gitignored.
**Verified**: the output dir holds `<stem>.exe`, `<stem>.manifest.json` and
`<stem>.ca.cer`; `Get-AuthenticodeSignature` → `STATUS=UnknownError` (host trust
untouched) with `SUBJECT`/`ISSUER` correct, and the exported `.cer` is the CA
(`HASKEY=False`); `version.dll` strings match the manifest `version_info`;
resources + signing combine; `subsystem: windows` audits as GUI. Examples:
`test-sign.yaml`, `test-fake.yaml`.
