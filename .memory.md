## Previous session: 2026-09-29 (batch 3: thread hijacking, stack spoofing, self-deletion)

**Three new techniques, 20 registered, all verified end to end on Windows.**
Numbers and the evidence tables: `docs/measurements.md` ("Batch 3").

- `thread_hijacking` (T1055.003, Execution, shellcode only): `target` (image
  name, or `pid`), `dedicated_stack` (private 1 MiB stack with a null return
  address, default true), `wait_ms`. Reuses `nt_open_process`,
  `nt_suspend/get/set_context_thread`, `nt_resume_thread`; no thread is created.
  Verified: a `ping.exe -t` hijacked with a `ud2` payload died with
  `0xC000001D`, which the loader relayed. Note: bash reports a child that exited
  with `0xC000001D` as "Illegal instruction"/132.
- `stack_spoofing` (T1036, Preparation, x64 only): replaces the syscall layer's
  trampoline (raw one renamed `nt_invoke_raw`), shifts `Rsp` by `decoy_bytes`,
  copies the nine stack arguments, fills the gap with ntdll `ret` sites resolved
  from the live ntdll at init, and unwinds a five-slot fabricated chain back to
  its own restore label. Verified: exit 42 relayed with 4 KB of decoy and with
  `0x80`..`0x8000`. Two findings: the fill loop used to write a block past the
  caller's `rsp` (symptom: a hang in the first spoofed syscall); and the clamp
  floor is `0x80` because `0x70`, the structural minimum, faults
  (`code_examples/stack_spoofing/bisect.py`).
- `self_deletion` (T1070.004, Preparation): `mode: rename_ads` (default) renames
  the running image into a random-named ADS of itself — verified: the path ends
  up 0 bytes with the 386 KB image in the stream — because a *mapped* image cannot
  be deleted on this build (four `FileDispositionInformation*` combinations
  measured `ERROR_ACCESS_DENIED`; see `code_examples/self_deletion/probe.cs`).
  `mode: helper` spawns a detached `cmd.exe` that deletes the file after the
  loader exits — verified: the file is gone from the directory.

**Also in this tree (uncommitted before this session):** the `techniques show`
styled-Markdown renderer + pager (`src/ui/markdown.rs`, `src/ui/pager.rs`), committed
separately.

**Open / next:** (1) explain the `0x80` cliff properly (a real disassembly of the
