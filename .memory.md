## Last session: 2026-09-28 (all 8 techniques implemented + error audit)

**Every registered technique is implemented and verified end to end.**
`cargo test` 525 bins + 16 CLI, clippy/fmt clean, `techniques validate` 17 OK,
leak gate green over 17 stubs. Numbers: `docs/measurements.md`.

- **Batch 1** (`execution_callbacks`, `module_stomping`, `fibers`): in-process
  shellcode runners, chainable; example plan `examples/plans/in-process-runners.yaml`.
- **Batch 2** (`unhook_ntdll`, `early_bird`, `pe_injection`, `ppid_spoofing`):
  four parallel agents, one directory each.
  - `unhook_ntdll`: **write window must be RWX** (a `PAGE_READWRITE` window faults
    on the syscall's return, which goes through ntdll's own stub inside the
    region being rewritten) and **x86 needs the section's base relocations**
    (19,004 bytes of HIGHLOW fixups vs the file).
  - `early_bird`: the payload's exit code cannot be relayed; returns
    `STILL_ACTIVE` unless a bounded `wait_ms` sees the target exit. The 32-bit
    `notepad.exe` of recent builds is a launcher shim — `QueueUserAPC` fails on
    it with `ERROR_INVALID_HANDLE`; `cmd.exe` / 64-bit notepad are fine.
  - `pe_injection`: resolves imports against the *target's* module bases and
    starts a thread at the entry point, without unmapping the target's image.
  - `ppid_spoofing`: `PROC_THREAD_ATTRIBUTE_PARENT_PROCESS`; the spoof was
    verified from PowerShell (`Win32_Process` reports the configured parent).
- One agent was lost to a context-limit failure and another was cancelled
  mid-flight; their work was still in the tree and I verified it myself
  (`pe_injection` x64/x86 + a stack probe vs its direct baseline; `early_bird`
  x64/x86 with the `ud2` APC proof).

**Fixes from the audit (mine):** `Params::default()` vs serde field defaults
(empty `target`); missing `validate_payload_format` rules for the new
techniques; `validate_injection_target` generalized to the three spawn-a-target
techniques; `nt_queue_apc`'s `_NONE` body now reports the real Win32 error
(`HRESULT_FROM_WIN32`) instead of a flat `STATUS_UNSUCCESSFUL`; the four
skeletons no longer ship a silent no-op (they fail loudly until implemented —
no longer needed now); docs: 6 missing technique rows/pages/nav/llms entries.

**New registry state: `Stability::Unimplemented`** (`Stable | Experimental |
Unimplemented | Deprecated`). A technique marked with it is registered but its
implementation is not finished; `techniques list` shows it in red and
`plan::validate::advisories` warns on every build that selects it (the build
still succeeds). `pe_injection` carries it today — measured: it works end to end
for TLS-free payloads (a `thread_local!` probe returns `7` injected), but the
payload's TLS is not provisioned like `process_hollowing`/`reflective_loading`
do, so it must not ship as-is. Flip it to `Experimental` when TLS lands.
Also found while probing: `pe_injection`'s DLL-identity guard rejects a target
whose copy of an imported DLL differs from the loader's (e.g. the Store-app
`notepad.exe` loading VCLibs' `VCRUNTIME140.dll`) — it fails loudly with the two
paths, which is the right call, but it is a real limitation to document.
