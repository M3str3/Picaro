## Previous session: 2026-09-27 (portable signing in the Docker image)

The container could compile but not sign (it needs the Windows SDK / `signtool`).
Signing now has two backends chosen by `signing::locate_signer`: **`signtool`**
(Windows) and **`osslsigncode`** (portable, in the image). `mode: lab` off
Windows generates a CA + leaf with `openssl` under
`<artifact dir>/.picaro/lab/<subject>/` (`PICARO_SIGN_DIR` overrides) and signs
the PEM chain; `mode: file` uses `-pkcs12`; `mode: store` errors clearly off
Windows (it reads the Windows cert store — the one thing a Linux container
cannot do). `-h sha256`, RFC 3161 `-ts`; `-out` never overwritten, so we sign to
a hidden sibling and rename. The Dockerfile installs `osslsigncode` + `openssl`
and its smoke test builds `examples/plans/lab-signed.yaml` and extracts the
signature. Verified in the image: `usable.yaml` signs, `osslsigncode verify
-CAfile …/ca.pem` reports `Signature verification: ok`, `file` (`.pfx`) works,
`store` fails as intended, `--dry-run` prints `osslsigncode /usr/bin/osslsigncode`.
Local `cargo test` (380 + 13), clippy clean. Note: `**/.picaro/` is gitignored.

## Previous session: 2026-09-26 (hollowing diagnostics obfuscated)

`audit out.exe` (x.yaml) flagged the technique keyword `loader`. Root cause: the
`process_hollowing` fragment returned cleartext `format!`/`to_string()` error
messages, one of them ("timed out waiting for the target **loader** to
initialize"). Fixed per the non-negotiable stub-literal rule:

- A `MESSAGES` table + loop in `process_hollowing/mod.rs::render_fragment` turns
  all 50 diagnostics into runtime reconstructions (like `$HOLLOW_TARGET_DEF$`).
  Call sites use the new fragment helper `nt_error(label, status)` or the label
  directly; values interpolate through keyword-free format literals, because
  `format!` cannot take a runtime format string.
- `reflective_loading` shellcode `#[error("the shellcode payload is empty")]` →
  "the payload is empty" — the only other runtime keyword. The other techniques'
  `thiserror` diagnostics are already keyword-free and stay cleartext.
- Verified: clippy/fmt clean, `cargo test` (371 + 13; +1 test asserting every
  catalogue message stays obfuscated), the `--ignored` guardrail, and real builds
  with **xor** and **stack**. `audit out.exe` now reads `technique names 0`; only
  `ntdll.dll` remains, marked `[imported]` (toolchain, not a leak).

## Technical debt

- `process_hollowing` only runs `format: pe`; shellcode/DLL are in-process only.
- DLL/shellcode args reach the payload through the PEB command line; a bespoke
  shellcode hand-off struct is out of scope.
- `$PAYLOAD_KEY_DEF$`/`$PAYLOAD_NONCE_DEF$` emit cleartext arrays in custom stubs.
- **TLS callbacks under hollowing** are not run (a never-started thread has no
  TLS array). The index/block/slot for the main thread *are* provisioned, and
  the payload completes.
- `process_hollowing`/`reflective_loading`: a payload that spawns threads and
  touches thread-local state on them has no TLS slot there either (same root
  cause as the callbacks).
- `bouncer`'s glob matcher and `Mode::accepts` are mirrored in the fragment and
  the packer (test-only reference); keep them in sync.
- `templates/stub/main.rs.tpl` keeps one runtime literal (MessageBox title)
  outside `StringsConfig` (harmless).
- Audit YARA engine is still a stub (`yara/README.md`).
- `inject.rs` needs ~40 bytes of header slack; a PE with none is rejected
  (`NoHeaderRoom`) rather than relocating the section table.
