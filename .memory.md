## Previous session: 2026-09-26 (hollowing TLS + syscall layer)

Made **process hollowing run a full PE** and finished the syscall-layer
migration:

- Found and fixed the real blocker: the hollowing fragment's relocation walk had
  `IMAGE_REL_BASED_HIGHLOW`/`DIR64` swapped, so an x64 image only had the low 32
  bits of every relocated pointer patched. Also fixed the entry hand-off
  (it set only `Rcx`, never `Rip`) and added the loader's TLS provisioning:
  `TlsAlloc` executed in the target (index read back from the thread's exit
  status), the index written where the payload reads `_tls_index`, a per-thread
  copy of the `.tls` template, and the main thread's TLS slot pointed at it.
  Measured: `dist/test_packed.exe` now prints its stub marker and exits `0`.
- `nt_invoke` now carries **eleven** argument slots with no stack shuffling.
  Measured fact that corrected the docs: `syscall` pushes no return address, so
  the kernel reads arguments 5+ from exactly the slots the x64 ABI put them in;
  the old `[rsp+8]` copies were no-ops and my first "fix" corrupted them.
- New helpers: `nt_create_thread_ex` (replaces `CreateRemoteThread`),
  `nt_wait_for_single_object`, `nt_query_info_thread` (TEB + exit status),
  `nt_set_context_thread`, `nt_close`. `process_hollowing` now uses only `nt_*`
  for kernel calls; `reflective_loading` runs the payload on the stub's own
  thread (no `CreateThread`), which is also the thread whose TLS slot is set,
  and provisions TLS via `TlsAlloc`/`TlsSetValue` + the `.tls` template.
- Verified: `cargo test` (354 + 13), clippy, fmt, `--ignored`
  `no_sensitive_literals_in_generated_stubs`, `indirect_syscalls_binary_runs_on_windows`,

## Technical debt

- `process_hollowing` only runs `format: pe`; shellcode/DLL are in-process only.
- DLL/shellcode args reach the payload through the PEB command line; a bespoke
  shellcode hand-off struct is out of scope.
- `$PAYLOAD_KEY_DEF$`/`$PAYLOAD_NONCE_DEF$` emit cleartext arrays in custom stubs.
- **TLS callbacks under hollowing** are not run (a never-started thread has no
  TLS array). The index/block/slot for the main thread *are* provisioned, and
  the payload completes.
- `process_hollowing`/`reflective_loading`: a payload that spawns threads and
  touches thread-local state on them has no TLS slot there either (same root
  cause as the callbacks).
- `bouncer`'s glob matcher and `Mode::accepts` are mirrored in the fragment and
  the packer (test-only reference); keep them in sync.
- `templates/stub/main.rs.tpl` keeps one runtime literal (MessageBox title)
  outside `StringsConfig` (harmless).
- Audit YARA engine is still a stub (`yara/README.md`).
- `inject.rs` needs ~40 bytes of header slack; a PE with none is rejected
  (`NoHeaderRoom`) rather than relocating the section table.
